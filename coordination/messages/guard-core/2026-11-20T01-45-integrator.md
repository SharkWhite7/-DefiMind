and 697/697 tests passed. Please send one small PR, GC-56, with these, in this order:

1. **Default RPC (blocks the one-click flow).**
   - The problem: with no SOLANA_RPC_URL from env or settings, buildChains throws "invalid
     configuration", so the first vault save answers 400 settings_incomplete. The panel says
     "leave empty for the default".
   - The fix: fall back to the cluster's public RPC, from rpcUrls({}) in
     @defimind/onchain/sign-page. Log once that it is rate-limited. GET /v1/owner/settings keeps
     rpcUrl absent in that case.
2. **Env RPC URLs leak through GET /v1/owner/settings.**
   - The problem: it returns an env-set rpcUrl verbatim, and a Helius URL carries ?api-key=. /sign
     now shares that origin.
   - The fix: return only the origin of an env-set URL.
3. **A lost key file makes a new hot wallet for an adopted vault.**
   - The problem: withKeys only treats the env's vault as "vault named". If chain_settings already
     holds a vault for the chain and the key file is gone, a new hot wallet is made without a word.
   - The fix: refuse the start and name the missing key.
4. **sign.ts reads its query without validation.** Parse it with zod.
