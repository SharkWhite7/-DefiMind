# The "ink" look: one professional visual language (PANEL-18, ON-26, SITE-7)

The owner saw the violet-to-mint polish (PANEL-16, ON-25, SITE-3) and asked for something else. In his
words: "quero algo mais dark com azul escuro" and "eu quero tirar aspectos de AI eu quero algo mais
profissional e unico como um dev profissional faria se nao existisse AI". He approved this mockup on
2026-11-23: [`overview-mock.png`](2026-11-23-ink/overview-mock.png), source
[`overview-mock.html`](2026-11-23-ink/overview-mock.html). Read the HTML. Its CSS is the reference for
every value below.

The rules of the [visual polish brief](2026-11-23-visual-polish.md) still hold:

- no behaviour, flow, route, API or validation change;
- no new dependency and no external resource (system fonts only);
- never truncate an amount, address, chain, token or expiry on the approval, kill or deposit screens;
- tests pass unchanged;
- before and after screenshots at 390×844, plus 1440×900 for the site and the signing page, from test
  data only.

This brief replaces the polish brief's look. The text rule changes in one place only: the Overview
header additions listed under PANEL-18.

## What goes

Every trace of the generated-template look:

- gradients of any kind, on text, buttons, borders, backgrounds or card accents;
- glows, blurs, coloured shadows and radial background washes;
- pills on every value;
- large radii;
- decorative motion beyond a 120 ms colour or opacity transition.

The violet `#9945ff` and mint `#14f195` leave the brand.

## The language

Tokens, from the mockup's `:root`:

| token                            | value                             | use                                      |
| -------------------------------- | --------------------------------- | ---------------------------------------- |
| `--bg`                           | `#0a0f1a`                         | page, header (solid, no blur)            |
| `--surface`                      | `#0e1524`                         | panels                                   |
| `--raise`                        | `#131c2e`                         | hover, inputs                            |
| `--line` / `--line2`             | `#1d2739` / `#2a3650`             | 1px hairlines; secondary button border   |
| `--text` / `--muted` / `--faint` | `#e7ebf1` / `#8792a5` / `#5d6879` | text levels                              |
| `--blue` / `--blue-hi`           | `#2c5ac8` / `#3a6ad6`             | the one action colour: solid, hover      |
| `--blue-ink`                     | `#9db7f0`                         | active tab underline, mark, meter, links |
| `--ok` / `--warn` / `--stop`     | `#3fb68b` / `#d9a441` / `#e5605c` | states only                              |

- **Shape.** 6px radius on panels and 5px on buttons and inputs. 1px borders, no shadows.
- **Type.** The system stack. Headings are weight 600, 20px on screens, never gradient. Labels are 11px
  uppercase with 0.08em tracking in `--muted`. Amounts use `tabular-nums` in the text face. Addresses,
  hashes and transaction ids use `ui-monospace` and wrap whole.
- **State.** A 7px square in the state colour, then the state's text ("Live", "Running", "Paused",
  "Shadow mode", "refused", "executed" and so on, whatever the screen already says). A request waiting
  on the owner gets a 2px `--warn` left rail on its panel. Chain names are plain text.
- **Navigation.** A solid header with a hairline under it. Tabs are plain text, and the current one has
  a 2px `--blue-ink` underline. Stop stays `--stop` text, pinned right. The mobile row scrolls, with no
  fade.
- **Buttons.** Primary is solid `--blue` with white text. Secondary and destructive are a 1px `--line2`
  border with `--stop` text for Reject, Revoke and Stop. On paired actions, the primary goes on the
  right and takes more width.
- **Mark.** The wordmark "DefiMind" in weight 600 `--text`, next to the square-in-square mark drawn in
  CSS or SVG with `--blue-ink`, as in the mockup. No glow. The site's and signing page's logo SVG switch
  to this mark. Panel PWA icons move to it if `icons.ts` makes that a small change; otherwise note it as
  a follow-up.

## Per surface

**PANEL-18, panel.** `app.css`, plus markup only where the layout needs it.

- Approved additions to the Overview header, built only from data the panel already fetches, with no new
  request and no new endpoint:
  1. a network indicator in the header ("● Mainnet" when every configured chain is a mainnet, else
     "● Devnet" or "● Testnet"). Derive it from existing chain ids; if it cannot be derived cleanly, drop
     it and say so;
  2. today's date beside the Overview title, in the browser's locale;
  3. the "Spent today" figure with a 3px meter of spent over the daily maximum. Use the existing
     per-chain budget values. With more than one chain, show one block per chain rather than summing
     different tokens;
  4. a three-cell summary: Agents (count), Waiting (pending approvals count), Chain(s) (names).
- Bigint money stays bigint, and the meter's ratio is computed in the domain with a unit test. That is
  the one new pure function.
- Every other screen keeps its content and takes the language.

**ON-26, onchain.** `style.css` and the brand header in `index.html`.

- Kill uses `--stop` for the title and a `--stop` left rail, with no top accent bar. Done uses `--ok`.
- Deposit's primary is solid blue.
- The "what this transaction does" box is a `--raise` panel in monospace.
- New `SHA256SUMS`, so the integrator re-verifies the deployed page after merge (it serves no one yet).

**SITE-7, integrator.** `site/index.html` and `whitepaper.html`.

- The same tokens, mark and rules: remove gradient text, the gradient bands, glows and decorative
  motion. Section labels in the uppercase label style; figures in tabular numbers.
- The hero becomes typographic: a strong headline and one line under it, with an optional real panel
  screenshot (test data) in a hairline frame.
- No copy change beyond what removing decoration needs. SITE-4 still waits.

## Done means

The checks of the polish brief, plus: no `linear-gradient`, `radial-gradient`, `box-shadow` (except
`none` and focus rings), `filter: blur` or `backdrop-filter` left in the changed CSS. Grep the diff and
say so in the PR. Each session sets its row to review and tells the manager the PR number.
