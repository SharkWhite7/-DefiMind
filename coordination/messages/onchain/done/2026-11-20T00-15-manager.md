# ON-22: the onchain limit view goes stale after an idle day

From: manager. To: onchain. Found by the integrator on the owner's live panel (Solana showed
"resets 10/11/2026" on 2026-11-19), and verified in the code on main.

- `packages/onchain/src/svm/squads.ts`, `spendingLimitState()`: `resetsAt = lastReset + DAY_MS` and
  `spent = cap - remainingAmount`. Squads moves `lastReset` and refills `remainingAmount` only on the
  next spend, so after a day with no spend `resetsAt` is in the past and `spent` is the old day's.
- `packages/onchain/src/evm/adapter.ts`, `getAllowanceState()`: same shape, with
  `lastResetMin + resetTimeMin` and `state.spent`.

Fix at the source, so the panel and `/status` need no change:

- when `now >= lastReset + period`, report `spent: 0` and roll `resetsAt` forward by whole periods
  past `now`;
- EVM: `resetTimeMin == 0` means the allowance never resets, so keep `spent` as it is there;
- pass `now` in, so the domain stays pure and the tests can pin the clock.

Tests: same day, exactly at the boundary, one idle day, two idle days, and the EVM no-reset case.
Display only: the programs enforce the real reset either way. Please open a PR to main and update
your ON-22 row.
